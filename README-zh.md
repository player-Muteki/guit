# guit

一个只管你眼前这份本地工作的桌面 Git 客户端。它在一个紧凑的窗口
里覆盖日常的本地 workflows——工作区状态、暂存、提交、分支、标签、历史、合并与
变基冲突——并可选置顶，方便和终端并排放着。

guit 用**你自己**安装的 `git`、**你自己的**配置运行。hooks、提交签名、凭据
helper 和 ssh-agent 的行为和在终端里完全一致，因为底下并没有藏着第二套 Git
实现。

**现状。** 在 Linux（Ubuntu、GTK/WebKit）上构建并运行。Windows 与 macOS 只做了
构建配置，从未在这里跑过，所以不声称可用。内存：面板是三个共享 GTK 与 WebKit 的
进程，其中约 130 MiB 是工具箱自己的，即使一个仓库都没开也已经在那里。在一个几千
文件的仓库上，它自己的部分大约 45 MiB，总共约 **180 MiB**
（按比例集大小 PSS 计）。它不随你的仓库历史增长——翻 6,000 个提交不改变这个数。
空闲时 CPU 低于单核的 1%，其中每五秒读一次 status，那是发现面板之外改动的下界。
哪些跑过、哪些没跑过，见 [Known limits](README-en.md#requirements)。

## 它有意不做的事

**guit 只处理本地。** 它从不联网：不克隆、不 fetch、不 pull、不 push、不强推、
不发布、不管理远端，也不弹任何凭据提示。你的远端配置和凭据设置原样不动，传输
本身留给终端。guit 在本地读到的是 Git 上次记录下的状态——类似 `origin/main`
的远端跟踪引用只作为这份本地元数据呈现，绝不被说成远端的当前状态。

**guit 从不显示文件内容和 diff。** 它不是编辑器。打开文件、查看 diff、解决冲突
这些动作一律交给你已经配置好的工具——`git difftool`、`git mergetool` 和系统
文件打开器。guit 不去和你真正读代码的地方抢位置。

也正因如此，guit 保持小巧：它持有的是你的仓库状态快照和能在这些状态上执行的操作，
而不是你工作区的内容。

## 环境要求

- `PATH` 上有 **Git 2.23 或更新版本**。（guit 启动时会探测是否支持 `git restore`；
  构建与验证使用的是 Git 2.53。）
- **Linux**，带 WebKitGTK 4.1 / GTK 3（包依赖会自动带入）。
- Windows 和 macOS 的包已配置、也能构建，但这个程序**从未在这两个平台上运行过**，
  因此在它们上的任何功能都按未验证对待。

### 实际跑过什么

在 Linux 上、在真实窗口里、对真实仓库验证过的：打开仓库并读它；暂存、取消暂存、
丢弃一个改动文件和删除未跟踪文件——每一步都经过确认，每一步事后都与 `git status`
和磁盘上的文件核对过；搜索；恢复到指定提交并走到它的预览；外观设置及其跨重启持久化；
四个窗口按钮；最小窗口尺寸；从损坏的、或比这个构建更新的配置文件里恢复。

有两件事由测试而不是由一次点击覆盖，这里写出来而不是让它们被默认包含：**提交**与
**恢复到指定提交号**都需要往一个输入框里打字，而这台测试机（一个没有按键注入工具的
Wayland 会话，且 WebKitGTK 的输入框不暴露 `EditableText` 接口）唯一的通道打不出字。
它们的行为由 Rust 测试套件和一支驱动真实视图的探针钉住，但没有由真人在真仓库上按过。

这里同样未验证的：多于一块显示器，以及报告不同缩放因子的显示器。

## 安装（Linux）

```sh
sudo dpkg -i guit_0.0.1_amd64.deb     # Debian / Ubuntu
sudo rpm -i guit-0.0.1-1.x86_64.rpm   # Fedora / openSUSE
```

AppImage 也能跑，但构建和运行都需要设置 `APPIMAGE_EXTRACT_AND_RUN=1`，因为
`appimagetool` 挂载镜像需要 FUSE：

```sh
APPIMAGE_EXTRACT_AND_RUN=1 ./guit_0.0.1_amd64.AppImage
```

## 上手

首次启动时 guit 的 Main 页是空的，只有一条进入路径：**打开**一个已经在磁盘上的
仓库。它会记住你打开过的仓库，下次启动自动恢复。克隆是 Git 自己的事——在终端里
克隆完，再来打开结果。

窗口只有两个页面，用应用栏里的 Tab 切换：

| 页面 | 上面有什么 |
| --- | --- |
| **Main** | 你的工作区，按冲突、已暂存、工作区改动、未跟踪分组。可就地暂存 / 取消暂存；每行的 `⋯` 菜单提供 diff、打开、丢弃、解决冲突。写完消息即可提交（可勾选 **Amend**）。分隔线（可拖动，两侧都保有下限）下面是当前分支的提交图，最新在前，**Load older** 逐页加载更早的历史，不会重建整个列表。两个区域同时可见——这个布局的意义就在于：暂存一个文件和读那张图，是同一眼就能看到的事。 |
| **Settings** | 主题与界面缩放、外部 diff/merge/打开工具、置顶、完整快捷键列表、环境检查（**Check again**），以及 **Export diagnostics…**。 |

应用栏里的分支标签会在 Main 之上打开分支与标签选择层：搜索、创建、切换、重命名、
删除分支，创建附注标签或轻量标签，并查看 Git 已记录在本地的远端跟踪引用。破坏性
操作先预览。它是一层临时的覆盖，不是第三个 Tab，所以它打开时 Tab 条依然可达。

即使没有打开仓库 Settings 也可用，因此主题、缩放和诊断在冷启动下依然可达；Main
在你打开仓库之前只显示空状态。

### 快捷键

| 快捷键 | 动作 |
| --- | --- |
| `Ctrl`/`Cmd` + `O` | 打开仓库 |
| `Ctrl`/`Cmd` + `R` | 刷新状态 |
| `Ctrl`/`Cmd` + `1` / `2` | 切到 Main / Settings |
| `Ctrl`/`Cmd` + `Enter` | 在消息框里提交 |
| `Ctrl`/`Cmd` + `=` / `−` / `0` | 界面放大 / 缩小 / 重置 |
| `Escape` | 关闭当前对话框、覆盖层或菜单 |

界面缩放范围 12–24px，主题默认跟随系统，也可手动覆盖。两种偏好在重启后都会保留。

## 破坏性操作绝不是一点即成

恢复到指定提交、删除分支、丢弃改动都走同一条路径：guit 先算出**确切**会影响到什么，
把这份清单给你看；如果在你确认之前候选集发生了变化，确认会被直接拒绝。恢复的那份清单
按路径的种类分开列出：两棵树有分歧的跟踪文件、会被丢弃的本地改动、会被写掉或被删掉的
未跟踪文件，以及那些让“干净状态”根本达不到的阻挡项——因为 `git reset --hard` 会不问一声
就把一个未跟踪文件写掉，面板宁可先说。一次确认
是单次有效的，并且随进程一起消亡——在对话框中途退出 guit，不会给你留下一个待执行的
破坏性动作，等你重启后一头撞进去。

## 只做本地，所以凭据仍然是你的

**guit 不保存任何凭据**——没有 guit 自己的凭据文件，没有 keychain 条目，也没有
内存缓存。它做得更彻底：因为 guit 不执行任何网络操作，它根本**不需要**凭据。没有
密码输入框，没有认证重试，也没有 askpass helper；guit 运行的每一个 `git` 都带
`GIT_TERMINAL_PROMPT=0`，所以一个远端不可达的仓库仍然是一份可读的仓库，而不是
一个卡住的提示。

你的 `credential.helper` 配置、你的远端和你的 ssh-agent 都被原样保留——
guit 也不读它们。

## 出问题时

Settings → Environment & diagnostics 里的 **Export diagnostics…** 会写出一份
纯文本报告。它会先给你看一份清单，说明这份文件**确切**包含什么：版本信息、
Git 可执行文件位置、文件监听模式、配置文件名及其字节数与 schema 版本，以及
近期事件摘要。凭据及其配置、远端 URL、提示文本、提交信息和文件内容从构造上
就被排除在外，home 目录路径也会被折叠掉。

## guit 会写哪些文件

配置放在你的平台配置目录，Linux 上是 `~/.config/dev.guit.desktop/`：

| 文件 | 内容 |
| --- | --- |
| `session.json` | 当前打开的仓库 |
| `recent.json` | 最近仓库列表 |
| `window.json` | 窗口位置、尺寸、最大化与置顶状态 |

这些文件**只向前迁移**。遇到比自己更新的 `schema_version` 时，guit 会拒绝读取
并原样保留字节，因此装上旧版 guit 绝不会改写较新的状态。只有更新的 guit 才会
写入更新的 schema，并且在写入时会把旧文件备份一份。
