# 06 开发路线与任务拆分

本路线按依赖排序，不给未经估算的日历日期。每阶段只有在退出条件满足后才进入下一阶段；发现平台关键能力不可用时先验证并调整设计，不继续堆功能。

## M0 工程与平台探针

**任务**：建立 `app/` Tauri 2 + TypeScript + Rust 工程、锁文件、最小 CI 和开发说明；检测系统 Git；验证三平台窗口置顶、缩放、路径选择、外部程序调用与进程取消。将验证结果、环境版本和未解决差异记录在计划中。

**交付**：可启动的空窗口、Git 能力检测页、平台探针记录、基础错误显示。

**退出条件**：三平台开发构建可重现；Git 缺失和不支持能明确提示；置顶可切换或已有明确的逐平台降级方案。

## M1 只读仓库工作台

**任务**：实现仓库识别、最近仓库、克隆、会话管理、porcelain v2 解析、状态分组、分支/上游摘要、刷新与文件监听。建立字节路径到文件 ID 的映射和旧快照失效规则。完成窄窗口布局、键盘导航与置顶状态记忆。

**交付**：用户可打开普通仓库、worktree 和裸仓库；可查看真实状态及基本反馈。

**退出条件**：空仓库、分离 HEAD、未跟踪、重命名、冲突、中文和空格路径均正确；裸仓库工作区动作不可用；多次快速刷新不会让旧快照覆盖新快照。

## M2 日常提交闭环

**任务**：实现暂存、取消暂存、全部暂存、丢弃、未跟踪清理、提交和 amend；实现外部文件/diff 工具、风险确认、临时提交消息、钩子错误反馈及写入队列。

**交付**：修改 → 外部查看 → 暂存 → 提交的完整 GUI 流程。

**退出条件**：写入后状态与 Git CLI 一致；丢弃/清理会列影响范围并在变化时重新确认；提交失败保留输入；操作中重复点击不会重复执行。

## M3 历史与引用

**任务**：历史分页和元数据、提交外部差异、分支创建/切换/重命名/删除、标签、上游信息。引入分支未合并风险和工作区有改动时的反馈。

**交付**：用户可在 GUI 中追踪提交并管理本地分支与标签。

**退出条件**：历史分页顺序稳定；引用变更后状态正确；名称非法、目标消失和未提交改动均能清楚处理。

## M4 进阶本地操作

**任务**：stash、merge、rebase、cherry-pick、revert、reset、worktree 和 submodule；实现进行中操作识别、冲突区、外部 mergetool、继续/中止动作。逐个动作补正常、拒绝、冲突及取消场景。

**交付**：计划定义的本地进阶流程可从 GUI 发起、跟踪和完成。

**退出条件**：冲突不会被当成普通失败；继续/中止仅在对应状态可用；危险重置、删除和 stash drop 需明确确认；worktree 的 Git 目录位置识别正确。

## M5 远端同步

**任务**：远端配置、fetch、pull、push、发布分支、设置上游和删除远端分支；实现进度流、拉取策略选择、认证失败分类、非快进处理及强推独立入口。按实际需要实现受控 askpass 桥接。

**交付**：本地裸仓库和真实远端的双向同步流程。

**退出条件**：普通与失败同步后引用状态一致；不会隐式强推；凭据不进入日志；取消后明确告知实际仓库状态。

## M6 性能与发布

**任务**：基于 100/1,000/10,000 文件及代表性大仓库测量启动、空闲、刷新和峰值占用；优化热点；完成三平台安装包、升级/配置迁移、用户文档和问题诊断说明。

**交付**：可安装版本和性能记录。

**退出条件**：满足 [07-quality-release.md](07-quality-release.md) 的功能、平台、性能和安全检查；无已知会造成未确认数据丢失的问题。

## 并行与依赖

- 窗口布局和状态解析可在 M1 并行，但都依赖 M0 的应用壳与命令桥接。
- 写入动作依赖稳定的文件 ID/快照协议与统一运行器，不能直接绕过 M1 的数据边界。
- 历史/引用可在 M2 后并行发展；进阶操作依赖写入队列、错误模型和风险确认。
- 远端同步依赖长任务进度和取消能力；认证桥接可先作为独立平台探针验证。

## 每个功能的任务模板

1. 写出用户动作、Git 命令、适用仓库种类和前置条件。
2. 列出正常、空结果、Git 拒绝、取消、外部并发改动的结果。
3. 添加解析/操作测试，再接入后端命令和 UI。
4. 验证窗口反馈、键盘可达、错误文本、刷新结果和日志脱敏。
5. 更新文档及性能数据；只有验收场景通过才标记完成。
