# 04 Git 引擎与操作安全

## 执行器契约

所有操作只通过一处 Git 运行器。调用方提交明确的工作目录、固定子命令、参数数组、期望输出模式、取消令牌和超时级别。运行器记录退出码与耗时，限制可缓存输出大小，长任务流式处理 stderr/stdout，并保留足够的脱敏诊断文本。不能通过 shell、字符串拼接或让前端传任意参数数组。

设置 `--literal-pathspecs` 或等效路径保护策略前应验证与现有 Git 配置和各命令兼容；路径参数统一置于 `--` 后。用户输入的分支名用 `git check-ref-format` 等能力验证；远端名和 URL 由固定参数位置和明确规则处理。不同动作的输入验证不能只靠 UI。

## 读取命令与解析

| 数据 | Git 来源 | 解析要求 |
| --- | --- | --- |
| 仓库身份 | `rev-parse --show-toplevel`、`--absolute-git-dir`、`--is-bare-repository` | 独立 worktree 中 `.git` 可为文件；裸仓库不强求工作树。 |
| 状态 | `status --porcelain=v2 -z --branch --untracked-files=all` | 解析 `#`、`1`、`2`、`u`、`?`；使用 NUL 分隔路径。 |
| 分支/标签 | `for-each-ref` 固定字段格式 | 分支名、目标 OID、上游与远端信息分别取字段，不解析颜色文本。 |
| 历史 | `log` 固定字段与分隔符、分页 | 消息可含换行；提交/字段边界不能依赖行数。 |
| 进行中操作 | Git 状态和受支持的 Git 查询/元数据 | 明确 merge、rebase、cherry-pick、revert 等；不得把内部文件名当唯一判断。 |
| 远端 | Git 配置查询或 `remote` 命令 | 展示 URL 前脱敏；区分 fetch/push URL。 |

状态解析器以字节处理 `-z` 输出。普通改动、重命名/复制、未合并和未跟踪记录的字段布局不同，必须分别解析；重命名还要读取紧随其后的旧路径。索引列和工作树列分别决定 `staged` 与 `unstaged`，冲突单独置顶。未出生分支、分离 HEAD、无上游及隐藏/忽略文件不能混为“干净”。

## 路径协议

后端持有 Git 输出的原始路径与可用于进程参数的系统路径。前端只拿文件 ID 和显示名；显示名允许转义或替换不可显示字符，但不能反向生成执行路径。旧快照文件 ID 在刷新后失效。重命名保存旧、新路径，调用 Git 时按动作选择正确路径。

Unix 非 UTF-8 文件名与 Windows Git 输出编码须有真实仓库测试。若后端无法无损往返某路径，UI 允许查看状态，但禁用该路径上的写操作并说明原因。选择仓库的绝对路径需做规范化；路径位于符号链接或工作树外时，以 Git 探测结果为准。

## 写入动作规则

| 动作 | 实现思路 | 操作前检查 | 完成后检查 |
| --- | --- | --- | --- |
| 暂存 | `add -- <path>` | 文件 ID 与快照一致 | 暂存状态重新读取 |
| 取消暂存 | `restore --staged -- <path>` | HEAD/索引状态允许 | 索引与工作树重新读取 |
| 丢弃工作区 | `restore --worktree -- <path>` | 列出受影响路径、确认 | 文件状态和错误重新读取 |
| 清理未跟踪 | `clean -n` 预览，确认后针对相同候选执行 `clean -f` | 重新预览；集合变化需再确认 | 不存在误删且状态刷新 |
| 提交 | `commit -F <临时文件>` | 消息、可提交状态 | HEAD 与索引状态、钩子结果 |
| 修改提交 | `commit --amend -F <临时文件>` | 当前提交、共享历史风险 | 新 OID、状态、上游风险提示 |
| 分支/标签 | `switch`、`branch`、`tag` | 名称、目标、未提交改动 | HEAD/引用表刷新 |
| stash/worktree/子模块 | 对应 Git 子命令 | 明确目标与工作区影响 | 新引用或工作树状态 |
| 合并/变基等 | `merge`、`rebase`、`cherry-pick`、`revert` | 目标 OID/引用、进行中操作 | 成功或冲突状态、继续/中止入口 |
| 远端操作 | `fetch`、`pull`、`push` | 远端、分支、拉取策略与上游 | 引用及领先/落后、失败状态 |

Git `clean` 预览与执行之间并非事务。应针对确认的路径集合运行；若无法保证目标与预览一致，拒绝执行并要求用户刷新。`reset --hard` 和强推应另设专用动作，不能把一个通用“重置”按钮映射成危险默认值。

## 提交消息、钩子和签名

提交消息用仅当前用户可读的临时文件传给 `commit -F`，保留多行内容；完成后删除临时文件，错误详情不得输出完整消息。钩子可能修改索引、提交信息或拒绝提交，失败后保留 GUI 输入并重新读取状态。签名依赖用户 Git 配置；外部签名程序需要交互时显示具体失败，不自动关闭签名。

## 网络、认证和取消

默认继承 Git 配置、SSH agent、凭据管理器。远端命令中 URL 必须脱敏后显示。先验证非交互凭据路径；若要支持需要输入的流程，设计受控 `GIT_ASKPASS` 辅助程序和一次性通信通道。只传临时凭据给 Git，不写应用配置或日志；如果安全桥接不可用，报错并引导配置系统凭据管理器。

克隆、抓取、拉取、推送的进度来自 Git 的流式输出，UI 显示阶段而非仅一个无法解释的百分比。取消尝试终止 Git 与可识别子进程，随后检查仓库是否留有未完成状态；不能承诺取消等于回滚。平台差异由集成测试覆盖。

## 外部工具

文件交给系统关联程序或配置的编辑器；diff 和 merge 优先沿用用户 Git `difftool`/`mergetool` 配置。每种工具先检查配置与可执行性，分清启动失败、工具非零退出和工具成功退出但仓库仍有冲突。外部工具参数模板由结构化参数组成，不通过 shell 展开。返回、窗口获焦和手动刷新均可重新读取状态。
