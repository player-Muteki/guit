# 01 产品范围与功能规格

## 用户和核心任务

目标用户是已使用 Git 的开发者，希望在独立、轻量的桌面窗口里管理仓库。入口包括打开现有仓库、克隆新仓库和最近仓库列表。典型任务是看到文件变化，借助外部工具查看内容，按文件暂存，填写提交信息并提交；之后查看历史、切换分支或同步远端。

界面参考 VS Code 版本控制侧边栏的信息密度和分组方式，但不依赖 VS Code。窗口可缩放、自适应、可切换置顶。不能把 Git 原始命令输出当作主界面；原文只用于错误详情和诊断。

## 必须保持的产品边界

- GUI 不呈现文件正文、diff 正文，也不提供文本编辑器。文件、差异和冲突分别由系统程序、外部 diff 工具和外部 merge 工具处理。
- 不执行任意用户输入的 Git 命令，不提供内置终端。界面动作对应后端定义好的语义操作。
- 不在应用设置和日志里保存密码、令牌、私钥或包含凭据的远端 URL。
- 不把 `git/` Git 源码镜像纳入构建。用户电脑须安装系统 Git；启动时说明缺失或版本不支持的情况。
- 不暗中执行强推、硬重置、清理或自动解决冲突。危险动作须显示目标和影响，并要求用户确认。

## 功能矩阵

| 领域 | 初次交付 | 后续阶段 | 明确边界 |
| --- | --- | --- | --- |
| 仓库 | 打开、最近仓库、克隆、识别普通/裸/worktree | 多仓库切换优化 | 裸仓库不出现工作区动作 |
| 状态 | 分支、上游、领先/落后、暂存、未暂存、未跟踪、冲突、重命名 | 大仓库降级展示 | 文件列表不加载内容 |
| 提交 | 按文件/全部暂存、取消暂存、提交、修改最近提交 | 更细的批量操作 | 不做逐块暂存，除非后续专门设计外部方案 |
| 历史 | 分页历史、提交元数据、复制哈希 | 筛选与定位优化 | diff 正文交给外部工具 |
| 引用 | 本地分支创建/切换/重命名/删除、标签 | 远端分支管理 | 删除前识别未合并风险 |
| 本地进阶 | stash、合并、变基、拣选、还原、重置、worktree、子模块 | 复杂图形编排 | 冲突解决交给外部 merge 工具 |
| 远端 | 远端管理、抓取、拉取、推送、发布分支、上游设置 | 交互认证体验优化 | 默认不强推，不擅自选择拉取策略 |
| 桌面 | 自适应、置顶、窗口状态、键盘导航、外部工具 | 多窗口可另行评估 | 首版以单主窗口为准 |

## 关键用户流程

### A. 日常提交

1. 打开仓库后显示当前分支、工作区/暂存区和冲突摘要。
2. 点击文件调用系统程序；点击“查看差异”调用已配置的 `git difftool`。外部程序关闭或窗口重新获焦时刷新状态。
3. 用户选择文件并暂存。GUI 重新读取快照，使暂存和未暂存的同名文件状态同时正确显示。
4. 提交前验证消息非空，提交后显示 Git 实际结果；钩子或签名失败时保留消息，不清空输入。

### B. 冲突处理

1. 在合并、变基、拣选或拉取产生冲突时，将进行中的 Git 操作和冲突文件固定展示在显眼位置。
2. 用户启动外部 merge 工具处理，返回后刷新；对未解决文件不提供“完成”假象。
3. Git 状态允许继续时才显示对应的继续动作，同时保留中止动作。中止后重新读取状态并告知可能保留的用户改动。

### C. 远端同步

1. 展示所选远端、当前分支、上游和领先/落后数量；无上游时先选择目标。
2. 抓取、拉取和推送显示进度与明确的目标引用。拉取策略不明确时要求选择或遵循用户既有 Git 配置，并展示实际使用的策略。
3. 网络、认证、非快进、保护分支拒绝应分别提示；失败后刷新仓库，不能只保留进度条结论。

## 风险等级与确认

| 等级 | 例子 | 交互 |
| --- | --- | --- |
| 只读 | 状态、历史、查看引用 | 直接执行，可取消长读取 |
| 可恢复写入 | 暂存、普通提交、fetch、创建分支 | 显示目标和结果；错误不吞掉 Git 原文 |
| 可能覆盖本地状态 | 丢弃、clean、reset、删除分支/worktree、stash drop | 执行前重新检查状态并显示影响集合；用户确认 |
| 影响远端他人 | 强制推送、删除远端分支 | 单独入口，确认远端、引用、影响；不提供默认勾选 |

## 完成定义

“完整”以功能矩阵列出的工作流为验收范围，而非 Git 全部子命令。每个功能必须有正常场景、拒绝场景、运行中反馈和完成后状态校验。无法由 GUI 完成的复杂底层操作可由用户的外部终端处理，但不能把功能矩阵中的任务隐含转嫁出去。
