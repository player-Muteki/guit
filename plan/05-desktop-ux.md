# 05 桌面界面与交互规格

## 信息架构

主窗口保持单一仓库焦点，采用类似版本控制侧边栏的垂直布局：

```text
仓库选择 / 当前分支 / 上游与同步摘要 / 置顶开关
进行中的操作与冲突提示
工作区文件组
暂存区文件组
提交消息及提交动作
状态/进度/最近操作反馈
```

历史、分支/标签、stash、worktree、远端和设置可以从主窗口菜单进入侧面板或独立视图。危险动作位于显式菜单，不与“暂存”一类高频按钮挤在一起。每个文件行展示状态符号、完整路径提示和可用操作；状态同时用文本或图标表达，不只用颜色。

## 布局与窗口

- 自由拖拽调整窗口，设不会破坏主要操作的最小宽高。窄窗口折叠次要信息和长路径，允许通过提示、复制路径或详情查看完整名称。
- 用户可设置界面缩放或跟随系统字体缩放；缩放后按钮、焦点环和确认对话框仍可操作。
- 置顶开关反馈应用后的真实状态，默认关闭。窗口恢复时校验屏幕边界，避免显示器移除后窗口落在屏幕外。
- 记录窗口位置、尺寸、最大化、当前仓库和置顶偏好；在异常退出后仍能以安全默认布局启动。
- 长文件列表虚拟滚动，折叠组保留状态数量。空仓库、干净仓库、无上游和 Git 不可用都有独立空状态。

## 主视图动作

| 区域 | 用户可见操作 | 禁用/异常状态 |
| --- | --- | --- |
| 仓库头 | 打开、克隆、最近仓库、手动刷新 | 非仓库显示选择或克隆入口 |
| 分支头 | 切换、创建、查看上游、同步 | 分离 HEAD 和未出生分支明确标示 |
| 工作区 | 打开文件、外部差异、暂存、丢弃 | 裸仓库禁用；不可往返路径禁用写入 |
| 暂存区 | 外部已暂存差异、取消暂存 | 无 HEAD 时须验证差异工具行为 |
| 冲突区 | 启动 merge 工具、查看 Git 状态、继续/中止 | 冲突未解决时不显示已完成状态 |
| 提交区 | 多行消息、提交、修改最近提交 | 失败保留输入；操作中防重复点击 |

## 外部工具体验

文件双击调用外部编辑器或系统默认程序。查看差异明确区分工作区差异与暂存差异，分别调用相应 Git difftool 模式。冲突文件调用 mergetool，并提示工具关闭后还需确认冲突已解决。未配置工具时提供设置入口、已检测到的 Git 配置以及复制路径/打开文件管理器的替代动作，不能弹出空白窗口。

## 确认和反馈

低风险操作用行内进度或通知；长任务有操作名、目标仓库、取消按钮和可展开原始输出。提交、拉取、推送等只在 Git 返回并完成刷新后宣告成功。失败通知保留到用户关闭或重试，不被下一次自动刷新覆盖。

危险确认框必须列出仓库、目标引用/文件数、可能丢失的数据类型及具体动作；强推额外显示远端和分支，不能只写“确定吗”。确认时如仓库状态已变化，先显示新状态并要求重新确认。非快进、未配置凭据、冲突、钩子失败等给出不同处理建议。

## 键盘与无障碍

从仓库选择到文件列表、提交框、主操作都可通过键盘到达；菜单、弹层支持 Escape 关闭和焦点返回。快捷键在设置中列出，避免与操作系统输入法和文本编辑冲突。列表项使用可读标签报告路径和状态，进度更新不过度打断屏幕阅读器。支持系统高对比度、缩放和减少动效偏好。

## 交互验证场景

1. 将窗口缩至最小，再放大到高 DPI 屏幕：主要动作无水平溢出且状态清晰。
2. 双屏环境中开启置顶、切换显示器、断开外接屏并重启：窗口可见，置顶状态可信。
3. 仓库同时有暂存和未暂存改动、重命名和冲突：各组计数与 Git 一致。
4. 外部编辑器修改文件、merge 工具退出后：不需重启应用即可看到实际状态。
5. 提交钩子拒绝、远端认证失败、用户取消 fetch：原始错误可查看，界面无虚假成功。
