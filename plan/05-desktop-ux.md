# 05 桌面界面与交互规格

## 信息架构

主窗口采用"应用栏 + 活动栏 + 视图"三段式布局，参考 VS Code 版本控制侧边栏的信息密度与分组方式，但保持独立运行：

```text
仓库选择 / 当前分支 / 上游与同步摘要 / 置顶开关
进行中的操作与冲突提示
工作区文件组
暂存区文件组
提交消息及提交动作
状态/进度/最近操作反馈
```

2026-09-25 的 M7 重设计把上述纵向长页面改为七个独立视图，由左侧活动栏切换，取代原先 10 张等权堆叠的卡片。变更、分支、远端等不再平铺在一条滚动流上，危险动作从与高频按钮并排改为行内 `⋯` 菜单或模态确认框。

### 活动栏视图

| 视图 | 内容 | 主要动作 |
| --- | --- | --- |
| Changes | 操作横幅、冲突/暂存/工作区/未跟踪四组折叠虚拟列表、固定提交页脚 | 按行暂存、批量暂存、丢弃、clean、外部工具、提交 |
| History | 虚拟提交列表 + 可拖拽分隔的提交详情 | 加载更早、复制 OID、外部差异、从提交建分支/标签、拣选、还原、三档 reset |
| Branches & Tags | 搜索框、新建分支/标签、分段引用列表、上游点选器、标签注解详情 | 切换、合并、变基、重命名、删除、设上游 |
| Stash | 消息框 + 存条目列表 | 保存、应用、弹出、删除 |
| Remotes | 添加表单、同步工具条、远端列表 | fetch/pull/push/publish、受限强推预览、用凭据重试 |
| Worktrees & Submodules | 工作树与子模块两段 | 新建/修剪/移除工作树，初始化并更新子模块 |
| Settings | General / Environment & diagnostics / Developer | 主题、界面缩放、置顶、Git 与外部工具探测、紧凑窗口测试、诊断导出、进程探针 |

### 应用栏

系统原生标题栏之下第一行：仓库名、分支芯片（含 `↑n ↓n`）、打开/刷新/克隆/关闭图标按钮、同步下拉（fetch / pull 策略子菜单 / push / publish）、提交按钮、置顶图钉、`⋯` 更多菜单。窄窗口（≤480px）隐藏仓库名与视图说明，保留分支芯片与全部图标动作。

### 空态与视图归属

未打开仓库时只显示欢迎态（打开仓库… / 克隆… / 最近仓库），不出现空视图框架。**唯一例外是 Settings**：主题、界面缩放、快捷键清单、环境探测与诊断导出都是应用级的，与仓库无关，因此无仓库时仍可达。其余六个仓库级视图在无仓库时置灰（`disabled`，title 提示"先打开仓库"），Ctrl/Cmd+1…7 也遵循同一条件，避免快捷键绕过置灰跳进空视图。

欢迎态正文保留 0.1.0 起 AT-SPI 回归脚本依赖的空态串 `Open a repository to list its working copy status.`；Changes 视图的空态因此只有 `Working copy is clean.` 一种。

### 反馈层

- 状态栏常驻底部：进行中的操作文本与取消按钮、监听模式、界面缩放控件。
- 失败以 Toast 栈呈现，最多 4 条，新的追加而非覆盖旧的，每条带关闭按钮。`plan/05` 要求的"失败通知保留到用户关闭或重试"由此满足（M6-05 记录的单告警位覆盖问题在 M7-03 修复）。
- 进度、结果、建议文案走状态栏，不用浮层打断。

## 布局与窗口

- 保留系统原生标题栏（`decorations` 保持默认），不设置 `decorations: false`。
- 自由拖拽调整窗口，最小 340×400。窄窗口折叠次要信息和长路径。
- 界面缩放（12–24px）与明暗主题（跟随系统，可手动覆盖）持久化在 localStorage，缩放后按钮、焦点环和确认对话框仍可操作。
- 置顶开关在应用栏与 Settings 两处可达，反馈应用后的真实状态，默认关闭。窗口恢复时校验屏幕边界。
- 记录窗口位置、尺寸、最大化、置顶偏好；异常退出后仍能以安全默认布局启动。
- 长文件列表与提交列表均虚拟滚动，折叠组保留状态数量。空仓库、干净仓库、无上游和 Git 不可用都有独立空状态。

## 主视图动作

| 区域 | 用户可见操作 | 禁用/异常状态 |
| --- | --- | --- |
| 应用栏 | 打开、克隆、刷新、关闭、切换视图、提交、置顶、同步 | 非仓库显示欢迎态；写入进行中禁用提交与同步 |
| Changes 文件行 | 暂存/取消暂存（常显）、打开/差异/差异暂存/解决冲突/丢弃（`⋯` 菜单） | 裸仓库无文件组；不可往返路径由后端拒绝 |
| Changes 组标题 | 全部暂存/取消暂存、全部丢弃、清理未跟踪 | 票据面板打开时禁用 |
| 冲突横幅 | 启动 merge 工具、继续/跳过/中止 | 冲突未解决时不显示已完成状态 |
| 提交页脚 | 多行消息、修改最近提交、提交（Ctrl/Cmd+Enter） | 失败保留输入；操作中防重复点击 |
| 引用行 | 切换（常显，仅非当前分支）、合并/变基/重命名/删除/设上游（`⋯` 菜单） | 当前分支不提供切换/删除；非 UTF-8 名只读灰显 |

## 外部工具体验

文件双击或行菜单的 Open 调用外部编辑器或系统默认程序。差异明确区分工作区差异与暂存差异，分别调用相应 Git difftool 模式。冲突文件经 `⋯` 菜单的 Resolve 启动 mergetool，提示工具关闭后还需确认冲突已解决。未配置工具时提供设置入口和检测到的 Git 配置。外部工具运行期间状态栏出现"Stop external tool"，退出后必然后置刷新。

## 确认和反馈

低风险操作用状态栏行内进度；长任务有操作名与取消按钮。提交、拉取、推送等只在 Git 返回并完成刷新后宣告成功。失败通知以 Toast 保留到用户关闭或重试，不被下一次自动刷新覆盖。

危险确认框改为原生模态 `<dialog>`：一个对话框服务 11 种票据种类，列出仓库上下文、目标引用/文件数、可能丢失的数据类型及具体动作；强推额外显示远端和分支。Escape 与取消等价于"保持现状"，焦点返回触发元素。状态在预览后变化时自动重发预览，候选变化则要求重新确认。凭据对话框是同一模态层的第二个对话框，其提交按钮不命名为 "Cancel"（M5-07 记录过同名取消按钮互相干扰）。

## 键盘与无障碍

- 活动栏视图可由 Ctrl/Cmd+1…7 切换；Ctrl/Cmd+R 刷新，Ctrl/Cmd+O 打开仓库，Ctrl/Cmd +/−/0 缩放，Ctrl/Cmd+Enter 提交。
- 文件列表 `tabindex=0` + 方向键在文件行间移动（跳过组标题、两端钳制）、Home/End 跳转、Enter 折叠/展开所在组，`aria-activedescendant` 报告当前行。提交列表为 `role=listbox`，方向键与 Home/End 移动选中。
- 菜单、模态支持 Escape 关闭和焦点返回。焦点来源不能只依赖 `document.activeElement`：WebKitGTK 在无控件持有焦点时把它停在滚动容器上，而经行内 `⋯` 菜单触发的动作其触发元素已经离树。`dom.ts` 因此记录最近被激活的可操作元素，模态与菜单从它取还焦目标。快捷键在 Settings → General 列出。
- 每个文件行左侧有 2px 状态轨，同时行首保留等宽两字母状态码（`M`/`A`/`D`/`R`/`U`/`??`），颜色从不单独承载信息。支持系统高对比度（`prefers-contrast: more` 加深分隔线）、缩放和减少动效（`prefers-reduced-motion: reduce`）。
- 活动栏按钮带 `aria-label` 与 `aria-current="page"`；图标一律 `aria-hidden`。
- **脚本写文本的裸 `<span>` 在 WebKitGTK 下不生成可及对象**，状态栏监听模式行与 Settings 缩放读数因此必须带 `role="status"`（它们本身就是要播报的变化），否则读屏用户听不到、AT-SPI 也测不到。其余承载文本的行（文件行、引用行、提交行）都在带 `role="listitem"`/`"option"` 的容器内，文本随容器聚合，无需额外角色。

## 视觉方向

低饱和表面 + 发丝级分隔线 + 单一强调元素（文件行左侧状态轨）。颜色令牌集中在 `style/tokens.css`，明暗两套值由 `prefers-color-scheme` 切换并支持 `data-theme` 手动覆盖；状态色取 GitHub Primer 语义色（新增绿、修改琥珀、删除红、冲突紫、未跟踪灰），与 GitHub 用户的既有认知一致。动效仅 120ms 颜色/透明度过渡，无阴影浮层。全部 16px 图标为手写内联 SVG 描边，不引入图标库。

## 交互验证场景

1. 将窗口缩至最小，再放大到高 DPI 屏幕：主要动作无水平溢出且状态清晰。
2. 双屏环境中开启置顶、切换显示器、断开外接屏并重启：窗口可见，置顶状态可信。
3. 仓库同时有暂存和未暂存改动、重命名和冲突：各组计数与 Git 一致。
4. 外部编辑器修改文件、merge 工具退出后：不需重启应用即可看到实际状态。
5. 提交钩子拒绝、远端认证失败、用户取消 fetch：原始错误可查看，界面无虚假成功，Toast 不被后续刷新覆盖。
6. 依次切换七个视图：活动栏选中态、视图标题与内容一致，无仓库时显示欢迎态而非空视图。
7. 打开一次丢弃/删除确认：模态列出候选，Escape 关闭后票据未消费。
