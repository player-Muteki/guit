基线为 `97b61dc`，最近两个提交加入并润色了原始大纲。本次读取了大纲、仓库指导、中文 README、限制说明、前端入口/状态/视图/窗口/字体、Rust 的快照/监听/历史/重置实现、测试及基准工具，并查看了相邻 `vscode-git-graph` 的功能说明和有关实现入口。

## 3. 偏离为什么发生在产品层

README 将产品定位为覆盖分支、标签、stash、合并/变基、远端、worktree 和 submodule 的桌面 Git 客户端，七个页面及其快捷键把这些能力放在同等层级。原始大纲要求的是无需切换页面就能看到工作区变化和历史的常驻小面板。

因此主要工作不是继续增加 Git 命令，而是改变信息架构、更新依赖和使用路径。隐藏活动栏而继续实例化全部视图、每个快照重读所有列表，也不能满足常驻低占用目标。

## 4. 直接影响目标的技术风险

### 4.1 监听不是文件活动模型

`watch.rs:149` 的事件回调将所有非 Access 事件转换为 `()`；事件路径和文件元数据没有进入快照。`.git` 元数据变化也会刷新状态，因此最后一次 watcher 信号不能用作“文件最后修改”。

`run_loop` 内部每次事件都把 quiet deadline 后移。静态上存在连续事件永不达到 quiet period 的路径；需要连续写入夹具验证，并增加最大等待。回调中的运行时 watcher 错误目前未形成明确降级事件，也应纳入目标监控链路。

### 4.2 历史身份不能仅依赖 HEAD

`views/history.ts:724` 附近以 HEAD OID 决定是否重新读取。相同提交的两个克隆仓库、同 HEAD 分支切换、只新增 Tag 或移动引用，都可能需要更新而 HEAD 未改变。

`loadPage` 请求使用 `oid: null`；Rust 分两次读取消息和拓扑。目标设计应把 session 身份、固定 HEAD、引用版本及请求代次纳入协议，并校验逐条 OID/parents 一致性。现有长度/索引检查不能替代这一契约。

`history.rs` 图超过 24 个活动轨道时退化到 first-parent 绘制并提示。它是一种已有诚实降级，但不能作为“完整拓扑”最终验收的默认策略；必须支持宽图浏览或明确边界并阻断无说明的简化。

### 4.3 hard reset 不等于所需干净状态

`reset.rs:79` 附近的 `tracked_dirty_set` 只列出已跟踪脏路径；当前说明认为未跟踪项不受影响。Git 的 hard reset 会覆盖阻挡目标检出的未跟踪文件/目录，而普通未跟踪文件又可能保留。

此外，从干净 HEAD 切到其他提交会改变目前不脏但与目标不同的已跟踪文件。新预览不能只复用现有脏文件列表来声称“全部受影响路径”。同一路径被 agent 再次写入也不一定改变路径集合；快照和票据本身不使外部文件写入原子化。

这里是静态发现的语义缺口；验证将在一次性夹具中进行，不对开发者工作区做实验。

### 4.4 图表匹配与引用分类

当前本地搜索过滤 commit 数组后继续使用原图行数据，需用“中间行不命中”夹具检查是否误接。新搜索采用独立结果与原图定位，可避免把筛选列表当作完整图。

`history.rs:295` 根据 `%D` 装饰文本分割标签；远端名称读取失败时退回空数组。新引用契约应直接保留 ref 类型和目标 OID，并区分未知、失败与空集合，避免把未知 remote label 当成本地 branch。

### 4.5 偏好和平台记录分散

窗口设置在后端配置文件，字号/主题在 localStorage；扩充三类字体、CSS 与计时前需要明确迁移和失效恢复。当前配置默认 720×560、最小 340×400；不能凭 README 的“紧凑”认定已满足上下同屏设计。

`docs/known-limitations.md` 只有 Linux 运行证据，Windows/macOS 是配置状态。基线指导文件称没有远端，但调研时 `git remote -v` 已显示 origin；该旧说明已修正，该事实不证明 CI 已运行。

## 7. 结论对应优先级

第一优先：同时观察的双 Tab 主面板、mtime 计时和不会饿死的监听。第二优先：稳定的完整图表与统一搜索。第三优先：按原始要求完成干净重置、字体/CSS 和四个窗口按钮。安全协议和测量贯穿全程；每项都属于本次完成范围，优先级不代表可永久延期。

仅本地边界在双 Tab 阶段就落地，并在最终发布时检查命令面、网络路径和文案，不能拖到“将来隐藏一个按钮”。
