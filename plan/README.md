## 改造方向

从当前覆盖多种 Git 工作流的七视图客户端，收敛到两个 Tab 的常驻监控面板。复用 Rust Git 后端、版本化快照、单写通道、单次票据、外部工具和虚拟列表，优先补齐“同时观察、最近文件修改、统一搜索”这条核心链路。

产品范围是**仅管理本地仓库，核心功能离线可用**。移除克隆、fetch/pull/push/强推、远端配置、远端删除和认证重试，不保留隐藏的远端入口。已保存的远端跟踪引用仅按本地元数据显示，不主动更新；缺失对象不隐式联网下载。

原始大纲明确的五组要求全部进入交付范围。搜索覆盖、mtime 范围、干净重置、默认置顶等未明确语义已经在大纲第 8 节写出采用的解释，避免实施者自行给出互不兼容的行为。

## 执行约束

- 本次只修改目标和计划文档，不执行应用改造，不对用户仓库做暂存、重置、清理等操作。
- `OUTLINE.md` 管产品边界，本目录管工程落地；`docs/known-limitations.md` 管验证限制，`CHANGELOG.md` 只记录已经完成的变化。
- 产品文案及其被扫描的文档/源码中不写开发阶段编号或本目录路径；当前 `app/tests/user-facing-copy.mjs` 不扫描本目录和大纲，无需放宽它。
- 既有本地能力先迁移入口再决定是否删除；远程能力同时退出 UI、自动任务及前端可调用命令。后端无调用的远程模块可分步清理，仍被本地功能使用的写保护和配置边界继续保留，不修改用户 Git 远端配置。
- 新增任务必须映射到 G01–G10，说明为何现有模块不能满足、对常驻开销的影响及验收方式。不能映射的工作不进入本次路线图。
