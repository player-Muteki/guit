# 07 验证、性能与发布

## 测试层次

| 层次 | 对象 | 主要案例 |
| --- | --- | --- |
| 解析单元测试 | porcelain v2、引用、历史、错误分类 | 普通/暂存/重命名/复制/冲突/未跟踪、分离 HEAD、无上游、NUL 路径、异常输出 |
| 后端集成测试 | Git 运行器和语义操作 | 临时仓库中的暂存、提交、钩子拒绝、分支、stash、冲突、worktree、子模块 |
| 远端集成测试 | 网络语义 | 本地裸仓库双向同步、非快进、上游缺失、被拒绝推送、取消长任务 |
| 前端单元测试 | 视图状态与操作控制 | 旧快照不能覆盖新快照、按钮禁用、风险确认、失败保留提交消息 |
| 桌面验证 | 平台边界 | 窗口缩放/置顶/恢复、外部工具、凭据、系统 Git 位置、安装/卸载 |

集成测试每次建立独立临时仓库，设置固定作者和隔离的 Git 配置，避免读取开发者个人全局配置。清理由测试夹具负责；失败时可按显式调试开关保留仓库。不能依赖本机已有网络或凭据完成核心自动化测试。

## 场景矩阵

| 维度 | 至少覆盖 |
| --- | --- |
| 仓库 | 空仓库、正常仓库、裸仓库、worktree、子模块、分离 HEAD |
| 文件 | 空格、中文、引号、换行、非 UTF-8 Unix 路径、Windows 边界路径、重命名和冲突 |
| 状态 | 未跟踪、忽略、仅暂存、仅工作区、两边都有改动、合并/变基进行中 |
| 外部变化 | 编辑器修改、终端提交/切换分支、远端引用变化、仓库目录移动/删除 |
| 错误 | Git 缺失、命令不支持、钩子拒绝、签名失败、认证失败、网络中断、非快进 |
| 取消 | 克隆、fetch、push、长时间钩子和外部工具返回 |

## 性能测量方法

选择同一台设备、相同系统版本和 Git 版本，分别测冷启动至可交互、后台空闲内存/CPU、状态刷新耗时、历史首屏与后续分页、峰值内存。仓库规模至少包含 100、1,000、10,000 文件，并记录未跟踪数量、存储介质和是否开启杀毒扫描。每项重复多次记录中位数和异常值，注明测量工具。

将 guit 与同环境中的 VS Code 版本控制侧边栏作参照，但明确比较范围：完整编辑器的总内存与单独客户端不完全等价。目标是找出启动或刷新中的明显瓶颈。第一轮原型数据形成基线，然后给出可验证的发布阈值；阈值或测量环境变化需留档。

## 安全与数据保护门槛

- 所有 Git 和外部工具命令均经参数数组执行，不经 shell；路径、分支名、URL 中含特殊字符的测试必须通过。
- 破坏性操作显示目标、风险和影响集合；确认后状态变化则重新确认。危险动作无默认选中。
- 凭据、含令牌 URL、提交消息临时文件及路径在日志中受到相应保护；诊断导出须让用户确认。
- 外部工具失败或用户取消后重新读取实际仓库状态；不能显示虚假的成功或“已回滚”。
- 解析错误、Git 输出截断、文件监听失效不能显示为“干净仓库”；要提示并提供手动刷新。

## 三平台发布检查

| 平台 | 特别检查 |
| --- | --- |
| Windows | WebView 依赖、Git for Windows 路径和编码、长路径、DPI、多屏、进程树取消、默认程序关联 |
| macOS | 应用签名/权限、系统 Git 或自装 Git、外部程序启动、窗口置顶、多屏和打包 |
| Linux | WebKit 运行依赖、不同桌面环境窗口置顶、发行版打包、默认程序与 SSH agent |

每个平台都要运行完整的打开、克隆、提交、冲突、同步、外部工具和窗口场景，不以构建成功代替运行验收。安装包在干净系统或隔离环境试装；检查首次启动、配置升级、卸载后用户数据处理和错误反馈。

## 发布资料与记录

发布前维护版本说明、已知限制、最低 Git/系统依赖、外部 diff/merge 工具配置、凭据方案及诊断方法。保存测试命令、平台版本、性能数据和未解决问题列表。首版发布的阻断项包括：未确认的数据丢失、错误目标强推/删除、秘密泄露、常见路径操作错误、平台无法启动或主要流程无法完成。
