# 全程改造路线图

状态：所有代码实施任务待开始。此文件给出从现状到交付的完整工作序列；不把文档编写算作应用完成，不承诺未经验证的发布日期。

## 1. 排期与推进方式

以一名熟悉 Tauri/Rust/TypeScript 的开发者为估算单位，净实施约 **40–62 人日**，另预留约 20% 用于复杂仓库和平台差异。可按 10–15 周安排评审窗口；这是规划范围，不是已验证工期。桌面测试资源不足、Unicode/主题解析依赖选择及干净重置边界可能改变估算。

| 阶段 | 预计人日 | 必须先完成 | 阶段产物 |
| --- | --- | --- | --- |
| A 基线、约束与语义夹具 | 2–3 | 文档基线 | 可比较的当前版本、待办和风险记录 |
| B 双 Tab 与本地范围收敛 | 5–7 | A | 真实数据的主面板、设置；远程入口/命令退出 |
| C 监听与文件修改计时 | 6–9 | B 的组件生命周期/会话标识 | 有界刷新、mtime 索引、可配置计时 |
| D 图表与引用协议 | 5–8 | B；A 的历史夹具 | 完整父链、稳定分页、气泡和分支选择 |
| E 统一模糊搜索 | 5–8 | D 的历史/引用上下文；B 顶栏 | 全范围渐进搜索和图定位 |
| F 提交与干净重置 | 7–11 | C 的刷新稳定性；D 的目标身份 | 安全预览、部分结果与最终状态闭环 |
| G 外观设置与窗口控制 | 5–8 | B 的布局；C 的计时偏好 | 字体、CSS、持久化和四个原生窗口动作 |
| H 迁移收尾与发布验收 | 5–8 | B–G 所有退出门槛 | 回归、基准、文档、包及验证记录 |

D 的后端夹具、G 的窗口 spike 可以在 C 期间按依赖穿插。任何阶段未满足安全/数据正确性门槛不能靠下一阶段的 UI 修饰放行。估算不隐含远端功能或为所有平台完成认证测试。

## 2. 阶段 A：可比较基线与核心语义

| ID | 工作与修改位置 | 交付及验收 |
| --- | --- | --- |

| A03 | 建立 mtime、连续写入、跨仓库同 HEAD、Tag 变动、深历史、多轨道与 reset 阻挡路径夹具 | 可稳定重现当前缺口；reset 只针对可销毁夹具 |
| A04 | 固定产品解释及“仅本地”命令清单；确认现有调用依赖 | 逐项关联 G01–G10；远程、克隆、认证、可能下载的 submodule 操作列入退出清单 |

退出门槛：能回答现有版本如何运行、哪些数据能信任、哪些风险需验证、哪些功能明确退出。没有桌面条件可先完成静态/纯测试，但运行基线标记未测，并在 H 前补齐。

| ID | 工作与修改位置 | 交付及验收 |

| B03 | 建立组件 dispose 和按域订阅；旧视图停止初始化/自动查询 | 不再一轮 snapshot 读取全部高级列表；Tab 往返不增加 timer/listener 数量 |
| B04 | 清理 welcome 克隆、shell 同步、remotes 页面、强推/发布/认证重试、submodule 下载入口；核对 `main.rs` invoke 注册与事件路由；阻止 partial clone 隐式取对象 | 核心功能离线可用；直接调用已退出的 IPC 也不可用；本地 refs 可读，缺对象不联网 |

退出门槛：主面板有真实更改和历史数据、两个 Tab、无远程操作入口或注册命令。尚未实现的搜索/计时不能伪装有功能的空控件；可使用明确的开发占位，但 H 前必须移除。

回退：组件提取、订阅迁移和导航切换拆开交付；B 内可恢复上一版主面板组件。仅本地约束已生效后，回退也不能重新开放远程动作。

## 4. 阶段 C：持续监控和 mtime 计时

| ID | 工作与修改位置 | 交付及验收 |
| --- | --- | --- |
| C01 | `watch.rs`：事件路径/种类保留、有界队列、最大等待、运行时失败降级。通道只送“有事发生”，路径在环路侧合并；无界 `mpsc` 需换成带容量的 `sync_channel` + `try_send`（实测事件率为每次写入 4 条 / 2 条非 Access，上界按此解释） | 连续事件不饿死刷新；队列溢出进入需核对状态（溢出不得当成无变化，也不得阻塞回调线程，实测满通道 `try_send` 约 26 ns 且不阻塞）；监听根被删又重建后事件重新被看见，Watch 模式在无事件时也按上界兜底刷新；停止/切仓库可取消 |
| C02 | 新 `activity.rs`：Git 候选枚举、metadata 索引、已跟踪/未跟踪/ignored/边界规则；`repo.rs` 的读取 helper 需先交出 stderr | 初始扫描 ready/partial/empty/unavailable 可区分（按 stderr 分，不按 stdout 空否分）；统计来自 mtime |
| C03 | 文件事件增量更新，最大项删除、rename、ignore/config 来源观察及目标更新：仓库内走事件，仓库外忽略来源只做有界 metadata 核对，不新增仓库外监听目标；休眠不检测，靠兜底 tick 恢复 | 不用最后事件时间代替 mtime；仅修改全局忽略文件也能在有界延迟内更新候选；丢事件后可恢复准确值 |
| C04 | `types.ts`/state/mainPanel/activityModel：绑定会话显示状态与相对时间；纯函数入口先按 `state` 分流再算年龄 | 仓库切换不显示旧时间；tick 不产生 Git 调用，不重绘完整图；未来 mtime 与时钟后退不产出年龄数字（也不产出负数/`NaN`）；六种状态各自有独立文案，`partial`/`stale` 不得冒充完整或新鲜 |
| C05 | 设置接入默认 5 秒、1–60 秒校验及临时持久化接口；与 G 的偏好模块统一 | 修改即时生效，只有一个计时器；未来迁移不丢此设置 |

退出门槛：用户在其他窗口连续改文件时，guit 仍更新；mtime 示例、删除最大值、忽略项、时钟异常、轮询降级和部分失败全部按契约呈现。日志能证明 idle tick 不触发 Git/全量扫描。

回退：监控 loop 与元数据索引分离。新 activity 读取失败可以显示不可用，不能用 watcher 时间临时代替。若最大等待方案失败，应保留现有合并 gate 并修复，不关闭失败提示。

## 7. 阶段 F：暂存、提交与干净重置闭环

| ID | 工作与修改位置 | 交付及验收 |
| --- | --- | --- |
| F01 | 更改区提交交互、单文件丢弃/清理、输入保存、busy/error 状态 | 提交只包含已暂存项；hooks/签名/取消失败保留草稿；丢弃均预览 |
| F02 | `reset.rs`：完整和唯一缩写 commit ID 解析，歧义/非 commit 拒绝 | SHA-1/SHA-256 按 Git 支持验证；不允许选项或任意 revspec 注入 |
| F03 | 新预览构造：目标树差异、脏路径、普通未跟踪、阻挡路径、保护边界 | 预览涵盖实际可能受影响项；ignored/嵌套仓库/submodule 阻挡时写前拒绝 |
| F04 | `write.rs` 票据扩展、同路径变化重查、单 lane 分步 reset/限定 clean | 消费后失败不复活票据；不清理票据外后来出现的文件；不声称消除外部写入竞态 |
| F05 | 执行后条件检查、取消/超时/部分完成结果与 preview renew | reset 成功但 clean 失败可辨识；新写入使工作树变脏时不报完全成功 |
| F06 | 更改区重置输入、预览分组/列表、确认文案和焦点 | 一次显式确认作用于当前预览；输入 Enter 不能绕过；窗口变化不藏住受影响清单 |

退出门槛：一次性仓库中全部破坏性操作场景有实证。预览范围错误、忽略项被覆盖或部分失败被报成功均阻断后续发布，不能靠文案降低承诺绕开修复。

回退：禁用未验收的新重置入口并保留失败原因；不把旧 hard reset 改名为“干净恢复”。代码回退不能恢复已清理内容，也不自动修改用户仓库以模拟事务回滚。

## 10. 风险与处理优先级

| 风险 | 触发信号 | 行动与负责阶段 |
| --- | --- | --- |
| 继续扩张为 Git 套件 | 新 Tab、网络动作、主面板高级按钮增加 | 按目标 G01/G10 拒绝纳入，B/H 审查 |
| mtime 扫描成本过高 | idle tick 启动 Git/全遍历，metadata backlog 无界 | C 分批/增量、stale 状态，H 测资源 |
| 搜索范围名实不符 | 第 51 条以后查不到却显示无结果 | E 全范围读取和 completion 状态，不以缓存命中代替范围 |
| 连续写入不刷新 | 事件持续但 Git capture 无启动 | C 最大等待和合并 gate fixture |
| 读不动的目录显示成干净 | Git 退出 0、stdout 只有分支头，stderr 非空（文本随语言变化，只判空不读文本） | C02 先让读取 helper 交出 stderr 并按契约分状态；快照与写前 recheck 同洞同批修 |
| 监听根丢失后静默 | 目录被删后事件归零且 notify 不发 `Err` | C01 保留事件路径识别 Remove(Folder)、按幂等 watch 重挂，Watch 模式加有界兜底刷新 |
| 图在切仓库或 refs-only 变化后陈旧 | 相同 HEAD 仓库共用页、标签不变 | B/D 会话身份和引用代次 |
| 重置遗漏损失路径 | 阻挡未跟踪项/干净但目标不同的路径未预览 | F 写前完整集合，未解决则禁用入口 |
| 外部 agent 再写入 | 检查后再次修改同路径、最终工作树仍脏 | F 重查/最终检查/部分结果；不承诺原子性 |
| 自定义 CSS 破坏可用性 | 关闭/禁用入口看不见、行高错位 | G 限定作用域/属性、恢复外壳与几何门槛 |
| 参考代码授权不适用 | 直接拷贝相邻项目代码/资源 | D/E 独立实现；复用前需另行解决授权 |
| 文档与实现混淆 | README 提前宣称新 UI/平台通过 | 全程只在实际完成后更新 shipped 文档 |

## 11. 每个实施任务的完成记录模板

任务实施时把以下记录追加到实际工程记录中；不要将未运行命令填为通过。

```text
任务：
对应产品目标：
起止提交与变更文件：
输入条件及 fixture：
实现行为与异常路径：
运行命令、退出码、日志位置：
桌面/性能证据与环境：
未解决限制：
回退方式：
结论：完成 / 受阻 / 需修订
```

每一阶段结束更新进度与证据；发生范围变化先改大纲，再改设计、路线图和验收矩阵，最后实现。仅本地与无文件内容两项边界不得因实现方便被隐式放宽。
