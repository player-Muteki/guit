# 全程改造路线图

状态：所有代码实施任务待开始。此文件给出从现状到交付的完整工作序列；不把文档编写算作应用完成，不承诺未经验证的发布日期。

## 1. 排期与推进方式

以一名熟悉 Tauri/Rust/TypeScript 的开发者为估算单位，净实施约 **40–62 人日**，另预留约 20% 用于复杂仓库和平台差异。可按 10–15 周安排评审窗口；这是规划范围，不是已验证工期。桌面测试资源不足、Unicode/主题解析依赖选择及干净重置边界可能改变估算。

| 阶段 | 预计人日 | 必须先完成 | 阶段产物 |
| --- | --- | --- | --- |
| A 基线、约束与语义夹具 | 2–3 | 文档基线 | 可比较的当前版本、待办和风险记录 |
| B 双 Tab 与本地范围收敛 | 5–7 | A | 真实数据的主面板、设置；远程入口/命令退出 |
| C 监听与文件修改计时 | 6–9 | B 的组件生命周期/会话标识 | 有界刷新、mtime 索引、可配置计时 |
| D 图表与引用协议 | 5–8 | B；A 的历史夹具 | 完整父链、稳定分页、气泡和分支选择 |
| E 统一模糊搜索 | 5–8 | D 的历史/引用上下文；B 顶栏 | 全范围渐进搜索和图定位 |
| F 提交与干净重置 | 7–11 | C 的刷新稳定性；D 的目标身份 | 安全预览、部分结果与最终状态闭环 |
| G 外观设置与窗口控制 | 5–8 | B 的布局；C 的计时偏好 | 字体、CSS、持久化和四个原生窗口动作 |
| H 迁移收尾与发布验收 | 5–8 | B–G 所有退出门槛 | 回归、基准、文档、包及验证记录 |

D 的后端夹具、G 的窗口 spike 可以在 C 期间按依赖穿插。任何阶段未满足安全/数据正确性门槛不能靠下一阶段的 UI 修饰放行。估算不隐含远端功能或为所有平台完成认证测试。

## 4. 阶段 C：持续监控和 mtime 计时

| ID | 工作与修改位置 | 交付及验收 |
| --- | --- | --- |
| C01 | `watch.rs`：事件路径/种类保留、有界队列、最大等待、运行时失败降级。通道只送“有事发生”，路径在环路侧合并；无界 `mpsc` 需换成带容量的 `sync_channel` + `try_send`（实测事件率按负载形状分两种：新建文件为每次写入 4 条 / 2 条非 Access / 1 条去重路径，反复追加同一文件为 ≈1 条非 Access / 恒定 1 条路径，所以两个上界不能由同一个“写入次数”换算；编辑器原子保存——写临时文件再 rename 覆盖目标——实测每次 5–6 条非 Access、1–2 条新路径，而深度这一维的答案是 0，且那些临时名在事件到达时**已不存在**，因此合并集必须按种类淘汰（`Remove` 与 rename 源侧删除），不得只进不出，plan/09 §1.4 末）；新增的任何节奏都不得改 `--no-optional-locks` 的**顶层**位置（写在 `status` 之后是 rc=129 的“未知选项”，量到过；`repo.rs:365-370` 的 prepend 是它唯一正确的位置，plan/09 §1.3 末）；同一条命令的带值选项一律 `=` 形式（空格形式会把值变成 pathspec，静默给出空集合，快照侧已为此写过注释，plan/09 §3.1） | 连续事件不饿死刷新（验收夹具必须包含“同一文件每 40 ms 追加”这一档：实测四种写入节奏的最大事件间隔是 22–42 ms，都对 250 ms 的 debounce 永不静默，只测新建风暴会漏掉最常见的形状；再加一档“每 40 ms 一次原子保存”，它同时检验饿死（最大间隔同为 41 ms）与合并集的淘汰规则——那 5–6 条事件里有一半指向已经被 rename 走的名字）；队列溢出进入需核对状态（溢出不得当成无变化，也不得阻塞回调线程，实测满通道 `try_send` 约 26 ns 且不阻塞）；监听根被删又重建后事件重新被看见，Watch 模式在无事件时也按上界兜底刷新（间隔已选定并量化：`POLL_INTERVAL` 5 s 作为 Watch 分支自己的 deadline，不新增具名常量、不按心跳计数，plan/09 §1.5；一次 tick 的实测合计本仓库 ≈4.0 ms、5,000 项夹具 ≈23 ms，@5 s 占空比 0.08% / 0.46%，@1 s 是 0.40% / 2.3%——最后一列就是不复用 5 s 的理由，而不是口味；硬约束是它只能是 `tick`（1 s）的整数倍，抖动上界 `tick + fire()`）；停止/切仓库可取消 |
| C02 | 新 `activity.rs`：Git 候选枚举、metadata 索引、已跟踪/未跟踪/ignored/边界规则；枚举是一条 `ls-files --cached --others --exclude-standard -z`（实测逐项等于两次调用的并集，输出是“未跟踪段+已跟踪段”而非全局有序，须按无类别集合处理；九种边界形状——空索引、嵌套仓库、gitlink、真 submodule、sparse、非法 UTF-8/换行/Tab/行首 `-`、暂存删除、全新目录——下这一逐项相等全部成立）；候选集**混着不是文件的项**：含 `.git` 的未加入目录是一个以 `/` 结尾的目录项，gitlink 是无尾斜杠的 `160000` 项，而目录 mtime 实测不跟随原地改写，所以只保留 regular file，`ENOENT` 跳过（sparse 的盘外已跟踪项属此类）、`EACCES`/`EIO` 才进 `partial`；剔除非文件项**只能靠 `lstat`**，不得按记录前缀形状分类（实测 `--stage` 会连带输出整个索引、未跟踪项即使带 `--stage` 也是裸路径，且存在与真实已跟踪记录逐字节同形的合法文件名，plan/09 §3.3，据此撤回的两处理由见该节标题）；输出触顶只有 `unavailable`——存活前缀是按类别偏置的（未跟踪段在前，触顶先丢已跟踪侧），不得当作一次低置信度 `partial`（plan/09 §2.2 末）；`repo.rs` 的读取 helper 需先交出 stderr，且**两个调用点同批处置**：recheck 侧按 `rc=0 ∧ stderr 非空 ⇒ 拒绝写入`（已量化——九个良性形状包括坏 `.gitignore` 模式、未初始化 gitlink、畸形 `.git/config` 都是 0 B stderr，唯一发 stderr 的那个目录读不动的形状恰好把已跟踪的修改与删除静默丢成 rc=0、0 条目，plan/09 §2.6 末）；活动值只能走 emit/listen（它不进快照），而这条面目前没有门禁——同一批提交里按命令面那套文本口径加上“emit 名与 listen 名双向配对”的夹具（在仅本地收敛之后实测两侧各 2 个且恰好一一对应，加上就是绿的；扫描必须能跨行匹配 `emit(`，后端有几处把名字写在下一行，按行匹配会把好代码读成不成对）；这条夹具**落在自己的测试文件里**，不往 `app/tests/ipc-surface.mjs` 追加——它正被改成按真实函数签名读绑定规则，而 HEAD 与并行工作树里该文件的 emit/listen 匹配数都是 0，门禁这条面仍是空的，同批不冲突（plan/09 §4.10 第 3 条）；emit 的**落点**也已定形：接在 `watch.rs` 的 `repo-refreshed` 之后、用同一个已发布的 view 取会话号（因此结构上不可能发出 capture 阶段的占位 0，也不可能读到下一个会话的号），`Err` 分支推一次 `unavailable` 而不是静默（静默等于让面板抱着上一次成功扫描的年龄不变），`stop()` 那类环路外的清理推一次**无身份**的清除——它是“清”不是“读”，与 `publishSnapshot(null)` 同形（plan/09 §4.10 第 4–7 条） | 初始扫描 ready/partial/empty/unavailable 可区分（按 stderr 分，不按 stdout 空否分）；统计来自 mtime；用了 sparse-checkout 或有子仓库的仓库不被永久显示成部分结果；事件名拼错必须让配对夹具失败，载荷键名对不上则由另一条断言 serde 键与 `types.ts` 字段一致的夹具接住——两条都不能省，否则面板只是静默不更新 |
| C03 | 文件事件增量更新，最大项删除、rename、ignore/config 来源观察及目标更新：仓库内走事件，重枚举用同一条**不带 pathspec** 的组合命令（实测范围只把 50k 量级的 14.9 ms 压到 5.3 ms，而写错的 pathspec 静默返回空集合——省不出这个失败形状）；仓库外忽略来源只做有界 metadata 核对，不新增仓库外监听目标（实测全局 `core.excludesFile` 与 `.git/info/exclude` 都在**下一次枚举**即生效，未跟踪的根/嵌套 `.gitignore` 同样生效；改一次全局文件不需要监听或重启）；休眠不检测，靠兜底 tick 恢复 | 不用最后事件时间代替 mtime；仅修改全局忽略文件也能在有界延迟内更新候选；丢事件后可恢复准确值 |
| C04 | `types.ts`/state/mainPanel/activityModel：绑定会话显示状态与相对时间；纯函数入口先按 `state` 分流再算年龄；接组件生命周期的 release 登记来关计时器，**不借快照 fan-out 驱动 tick**（按内容去重的通知会把每次 tick 吞掉，把 `now` 塞进键又等于全量重绘）；那一行必须是更改区**建面板时就存在的直接子元素**——区域下限按量算，放到区域外就少一行，按需插入的子元素不在观察列表里；载荷用 `types.ts` 的共享类型而不是就地匿名结构，认不出的 `state` 值进 `unavailable`，**不得折进任何一个已知状态**（现有 `watch-status` 就是把未知 mode 折成“看起来健康”的那一档的反例） | 仓库切换不显示旧时间——机制已随 B05 的工作树定形：活动载荷带后端铸造的 `sessionId`，与同批快照里那个相等才显示，否则丢弃；它**不是** `ReadContext.generation` 那个域世代计数，两个数不同步，混用等于把活动值绑在一个它会误判的键上；emit 必须排在 `publish` 之后（capture 阶段的 id 是 0，没有任何真实会话认领它），且不得在 publish 后回读 `SessionState` 取 id（plan/09 §4.10 第 1、2 条）；tick 不产生 Git 调用，不重绘完整图；未来 mtime 与时钟后退不产出年龄数字（也不产出负数/`NaN`）；六种状态各自有独立文案，`partial`/`stale` 不得冒充完整或新鲜；先按 A02 记录里“分隔条那一提交之后复判”那一条重跑一次同口径 idle 基数，再报 C 自己的开销（基数已含新增的三个观察器，不复跑则差值不可归因）；读预算探针今天只数前端 `invoke` 与一次性 `setTimeout`，看不见周期定时器与事件释放——释放不是被桩掉了，而是 `_unlisten` 在到达 invoke 之前就因缺 `__TAURI_EVENT_PLUGIN_INTERNALS__` 而 reject（活动契约 §4.9 第 1 条，选定见同节末），所以“不泄漏”必须由 C04 自己那条能失败的断言给出：按 §4.9 选定补该探针的两列（`setInterval`/`clearInterval` 独立计数，绝不折进 `pending`；补那一个全局后 `plugin:event\|listen` 与 `plugin:event\|unlisten` 现成成对），并在实现说明里写明它不进 `npm run test:fixture`、是一条单独运行的证据 |
| C05 | 设置接入默认 5 秒、1–60 秒校验及临时持久化接口；沿用主面板分隔比例那套形状（纯模块里的 `clamp*` + `readStored*`、`guit.<camelCase>` 键、读写各自 try/catch、存储不可用回默认），与 G 的偏好模块统一 | 修改即时生效，只有一个计时器；未来迁移不丢此设置 |

退出门槛：用户在其他窗口连续改文件时，guit 仍更新；mtime 示例、删除最大值、忽略项、时钟异常、轮询降级和部分失败全部按契约呈现。日志能证明 idle tick 不触发 Git/全量扫描。

回退：监控 loop 与元数据索引分离。新 activity 读取失败可以显示不可用，不能用 watcher 时间临时代替。若最大等待方案失败，应保留现有合并 gate 并修复，不关闭失败提示。

| F01 | 更改区提交交互、单文件丢弃/清理、输入保存、busy/error 状态 | 提交只包含已暂存项；hooks/签名/取消失败保留草稿；丢弃均预览 |
| F02 | `reset.rs`：完整和唯一缩写 commit ID 解析，歧义/非 commit 拒绝 | SHA-1/SHA-256 按 Git 支持验证；不允许选项或任意 revspec 注入 |
| F03 | 新预览构造：目标树差异、脏路径、普通未跟踪、阻挡路径、保护边界 | 预览涵盖实际可能受影响项；ignored/嵌套仓库/submodule 阻挡时写前拒绝 |
| F04 | `write.rs` 票据扩展、同路径变化重查、单 lane 分步 reset/限定 clean | 消费后失败不复活票据；不清理票据外后来出现的文件；不声称消除外部写入竞态 |
| F05 | 执行后条件检查、取消/超时/部分完成结果与 preview renew | reset 成功但 clean 失败可辨识；新写入使工作树变脏时不报完全成功 |
| F06 | 更改区重置输入、预览分组/列表、确认文案和焦点 | 一次显式确认作用于当前预览；输入 Enter 不能绕过；窗口变化不藏住受影响清单 |

退出门槛：一次性仓库中全部破坏性操作场景有实证。预览范围错误、忽略项被覆盖或部分失败被报成功均阻断后续发布，不能靠文案降低承诺绕开修复。

回退：禁用未验收的新重置入口并保留失败原因；不把旧 hard reset 改名为“干净恢复”。代码回退不能恢复已清理内容，也不自动修改用户仓库以模拟事务回滚。

## 10. 风险与处理优先级

| 风险 | 触发信号 | 行动与负责阶段 |
| --- | --- | --- |
| 继续扩张为 Git 套件 | 新 Tab、网络动作、主面板高级按钮增加 | 按目标 G01/G10 拒绝纳入，B/H 审查 |
| mtime 扫描成本过高 | idle tick 启动 Git/全遍历，metadata backlog 无界 | C 分批/增量、stale 状态，H 测资源 |
| 搜索范围名实不符 | 第 51 条以后查不到却显示无结果 | E 全范围读取和 completion 状态，不以缓存命中代替范围 |
| 连续写入不刷新 | 事件持续但 Git capture 无启动 | C 最大等待和合并 gate fixture |
| 读不动的目录显示成干净 | Git 退出 0、stdout 只有分支头，stderr 非空（文本随语言变化，只判空不读文本） | C02 先让读取 helper 交出 stderr 并按契约分状态；快照与写前 recheck 同洞同批修 |
| 事件投递静默失败 | 后端 `emit` 与前端 `listen` 的名字两侧无任何门禁；载荷是就地匿名类型，认不出的值被折进“看起来健康”的那一档（现有 watch mode 分支即为反例） | C02 加“两侧名字双向配对”夹具并断言 serde 键；C04 用共享类型接收，认不出的状态判为不可用 |
| 监听根丢失后静默 | 目录被删后事件归零且 notify 不发 `Err` | C01 保留事件路径识别 Remove(Folder)、按幂等 watch 重挂，Watch 模式加有界兜底刷新 |
| 探针绿灯被当作无泄漏证据 | 读预算探针只数前端 `invoke`、`window`/`document` 监听与一次性 `setTimeout`：事件释放（`unlisten`）今天到不了计数——`_unlisten` 先读一个探针从未定义的 `__TAURI_EVENT_PLUGIN_INTERNALS__` 并就此 reject（注册本身是可见的，走 `plugin:event\|listen`，只是没有任何断言读它）；`setInterval` 不在它的计数列里，后端自己 spawn 的 git 更与它无关 | C04 的定时器与监听由自己那条能失败的断言证明（活动契约 §4.9 末的选定：补那一个全局 + 独立一列周期定时器，断言取注册/释放差值在十二次往返前后相等）；“idle 不常驻执行 Git”仍以 `GUIT_PERF=1` 阶段日志/后端 spawn 计数字径，不由这条探针结案 |
| 目录项被当成候选文件 | 不带 pathspec 的枚举里，含 `.git` 的未加入目录是一个以 `/` 结尾的目录项，gitlink 是无尾斜杠的 `160000` 项；目录 mtime 不跟随原地改写，只在增删条目时动 | C02 只保留 regular file；`ENOENT`（sparse 盘外项）跳过、`EACCES`/`EIO` 进 `partial`；子仓库内部不覆盖写入限制记录 |
| 图在切仓库或 refs-only 变化后陈旧 | 相同 HEAD 仓库共用页、标签不变 | B/D 会话身份和引用代次 |
| 重置遗漏损失路径 | 阻挡未跟踪项/干净但目标不同的路径未预览 | F 写前完整集合，未解决则禁用入口 |
| 外部 agent 再写入 | 检查后再次修改同路径、最终工作树仍脏 | F 重查/最终检查/部分结果；不承诺原子性 |
| 自定义 CSS 破坏可用性 | 关闭/禁用入口看不见、行高错位 | G 限定作用域/属性、恢复外壳与几何门槛 |
| 参考代码授权不适用 | 直接拷贝相邻项目代码/资源 | D/E 独立实现；复用前需另行解决授权 |
| 文档与实现混淆 | README 提前宣称新 UI/平台通过 | 全程只在实际完成后更新 shipped 文档 |
