# 02 技术栈与平台前提

## 已选组合

| 位置 | 技术 | 使用方式 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | 原生窗口、系统 WebView、命令桥接、打包和平台能力 |
| 界面 | TypeScript、HTML、CSS | 原生 DOM 组件和小型状态层；初期不引入大型前端框架 |
| 后端 | Rust | 仓库会话、Git 进程、解析、操作队列、设置、外部工具 |
| Git 执行 | 用户安装的 Git CLI | 沿用 `.gitconfig`、钩子、签名、SSH agent、凭据管理器 |
| 配置 | 版本化 JSON | 应用配置目录，原子替换和迁移；不保存凭据 |
| 测试 | Rust 单元/集成测试、TypeScript 单元测试、桌面平台验证 | 临时仓库和本地裸仓库驱动真实 Git |

依赖尽量少，但不为了“零依赖”重写已有可靠能力。引入每个包前记录用途、维护状态、包体/运行时影响和替代方案。前端不依赖 Chromium 打包；系统 WebView 依赖由各平台安装包或先决条件满足。此处不预先指定尚未查证的插件和版本。

## 必做的技术验证

1. **环境**：在三平台确认 Tauri 2 构建依赖、系统 WebView、可用 Git 位置、安装权限；写成开发环境说明。
2. **窗口**：做最小窗口实验，验证置顶开关、最小尺寸、位置恢复、DPI/系统缩放、多屏幕边界；若平台行为不同，定义清晰降级。
3. **Git 版本**：列出实际使用的所有命令参数，在最低目标版本上运行功能探针。启动时据此给出支持与否，不仅比较版本字符串。
4. **外部工具**：验证 `git difftool`、`git mergetool` 在三平台的配置、退出码、启动失败和工具关闭后刷新；系统默认打开文件可能没有可等待的子进程，窗口获焦刷新须兜底。
5. **路径编码**：用中文、空格、引号、换行、非 UTF-8 Unix 路径及 Windows 特殊路径建立测试仓库，验证从 Git 输出到再次传入命令的往返。
6. **取消**：确认长时间 Git 进程、钩子、SSH 和凭据程序的取消语义。无法可靠终止进程树时如实显示“取消请求已发送”，之后仍要复查状态。

## 依赖与构建规则

- `app/` 拥有自己的 Rust 和前端锁文件；CI 使用锁定版本，按明确流程升级。
- Rust 的 Git 命令接口不依赖前端运行环境，可在无 GUI 条件下测试。
- 应用安装包不包含根目录 `git/`；构建脚本不能引用其内部文件。
- 用系统 Git 路径与版本作为运行时诊断信息。用户可在设置中指定 Git 可执行文件，但路径必须指向可执行文件并经过版本/能力探测。
- 不依赖 shell 管道或用户 shell 配置来完成 Git 操作；所有参数通过进程 API 传递。
- Git 进程需要的环境变量由后端集中设置或继承，避免各模块行为不一致。

## M0 实测基线（Linux，2026-09-23）

完整证据见 [M0-validation.md](M0-validation.md)。锁定并验证的版本：Tauri CLI 2.11.5 / `@tauri-apps/api` 2.11.1 / tauri crate 2.11.6、`tauri-plugin-dialog` 2.x、Rust 1.96.1、Node 22、Git 2.53.0（`status --porcelain=v2 -z --branch` 能力探针通过）、WebKitGTK 2.52.6、GTK 3.24.52。运行时验证得到的技术结论：

- `git difftool` 默认忽略 diff 工具退出码，必须传 `--trust-exit-code`（或配置 trustExitCode）才能感知失败；`mergetool` 需 `mergetool.keepBackup=false` 避免 `.orig` 残留。
- GNOME Wayland HiDPI（scale=2）下 `outerSize`/`innerSize` 上报值含缩放偏差，直接保存会逐次重启增长；窗口设置改为保存视口像素（`innerWidth × scaleFactor`）+ 实测边框增量恢复。
- 取消采用进程组终止（Unix `kill(-pgid)`、Windows 进程树 `taskkill /T /F`），超时须终止持有管道的后代进程，否则输出读取悬挂。
- Git 子进程环境集中构造：剥离继承的 `GIT_*`，设置 `GIT_CONFIG_NOSYSTEM`、`GIT_CONFIG_GLOBAL`、`GIT_TERMINAL_PROMPT=0`（仅隔离探针；用户仓库操作沿用其自身配置）。
- 无法截图时可用 AT-SPI（`gi.repository.Atspi`）驱动和断言窗口控件状态，作为 GUI 运行时验证手段。

## 资源占用策略

启动时只加载主视图、最近仓库设置和当前仓库状态；历史等面板按需加载。列表使用虚拟滚动；历史按页读取。对文件监听事件防抖，对后台窗口降频。避免在每个文件上单独运行 Git。任何缓存必须有明确失效条件；仓库写入后以 Git 实际输出重建快照。

资源目标不以未经测量的固定 MB 或毫秒承诺。原型阶段先记录设备、操作系统、Git 版本、仓库规模和测量方法，再在 [07-quality-release.md](07-quality-release.md) 中设置可重复的发布基线。

## 替代方案触发条件

- 如果原生 DOM 状态代码出现大量重复或难以维护，先做小型组件化重构，再评估轻量框架；评价依据是代码复杂度和运行指标。
- 如果单次完整 `status --untracked-files=all` 对目标大仓库耗时过高，改为按目录展示未跟踪项、后台增量刷新或允许用户选择扫描深度；不能悄悄漏掉文件。
- 如果某平台无法通过 Git 配置稳定启动外部 diff/merge 工具，则在设置中支持明确的可执行文件与参数模板，并在该平台做独立测试。
