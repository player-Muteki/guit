- [x] **M4-04** 实现 reset 模式选择；`--hard` 单独高风险入口，不做默认按钮。
  - 证据（2026-09-24，Linux / Git 2.53）：新模块 `reset.rs`。**模式分级**：`reset(snapshot_version, mode, target)` 的 `mode` 在 Rust 侧是 `#[derive(Deserialize)] ModeArg { Soft, Mixed }`——序列化面上 **"hard" 根本不可表达**，硬重置只能经独立命令 `reset_hard(nonce)` 消费一次性票据（`PreviewKind::ResetHard`），History 详情三档按钮中 hard 为 danger 样式且无默认入口。**目标校验**：三档共用 sequencer 校验（完整 OID 或 `for-each-ref` 唯一本地分支名，`HEAD~1`/`@{u}`/尾随空格名等在触达 Git 前 Rejected）；soft/mixed 对格式合法但不存在的 OID 交由 Git 自身失败并透传脱敏 stderr。**票据承诺**（preview 时冻结、confirm 时全量复查）：目标解析出的 commit OID、当时的 HEAD OID、跟踪脏文件（索引或工作区任一有改动；unmerged 计入；纯未跟踪不计，因 hard reset 不触碰它们）的精确集合——confirm 时任一漂移（工作区被外部再改、分支被外部移动、目标被 gc、换了仓库会话、又有操作进行中）都在启动 Git 前 Rejected 且断言 `exit_code=None`、现场未被回写。实测钉死一个破坏性细节：**仅暂存（未提交）的新文件会被 `reset --hard` 从磁盘删除**（Git 对索引内条目的覆盖语义），因此预览清单必须列出暂存新增（测试 `hard_reset_lists_targets_and_only_then_applies`），纯未跟踪文件则必然幸存；预览 `dropped` 列 = `rev-list HEAD ^target`（>20 条时截断并如实报总数）。进行中 merge 之上发起任何 reset 均拒（复用 in-progress 闸门）。测试新增 7 项（全量 171，Linux）：soft 只动 HEAD（索引/文件逐字节不动，`git show :a.txt` 断言）、mixed 还原索引（暂存新增退为未跟踪、文件仍在）、hard 预览→确认→票据耗尽重放拒、脏集合漂移拒、HEAD 漂移拒、非法目标矩阵拒、进行中/陈旧版本拒。缺口：AT-SPI 点击冒烟并入 M4-08；Windows/macOS 未实测。
