  - 证据（2026-09-24，Linux / Git 2.53）：新模块 `stash.rs` + 7 个命令（`stash_list`/`stash_save`/`stash_apply`/`preview_stash_pop`/`stash_pop`/`preview_stash_drop`/`stash_drop`）。前端只提交 `u32` 位置索引，`stash@{N}` 选择器字符串仅由后端拼装（`selector_cannot_be_typed_by_the_client` 钉死注入面为零）。列表解析 `%gd%x1f%cI%x1f%s`（实测 Git 2.53 不解释 `%1f`，必须 `%x1f`；`%s` 折行保证记录不跨行）：选择器与位置交叉校验，形状不符即 `stash_protocol_error` fail-closed（`parse_is_fail_closed_on_shape_and_position`，含消息内嵌原始 0x1f 的宽容提取）。实测陷阱：干净工作区 `git stash push` 返回 rc=0 "No local changes to save"，故 save 前必做脏集合复查（`stash_nothing` 拒绝，绝不把无操作当成功）；冲突文件在场时拒绝 save（`stash_conflict`，merge --no-edit 冲突夹具实测）；unborn HEAD 拒绝；未跟踪文件默认不入 stash（round-trip 测试断言 `keep.txt` 幸存，UI 按钮 title 明示）。pop/drop 复用一次性票据（`PreviewKind::DropStash/PopStash`，oid 于预览时经 `rev-parse --verify` 捕获、确认时重算比对，位置漂移即拒），重放/跨 kind 消费均拒；apply 无票据但复查条目存在性。取消（Git 前）仍强刷快照且不产生 stash 条目；bare 仓库可读列表、一切写操作拒。10 个新 Rust 测试（`cargo test --locked` 143 通过），`tsc --noEmit`+vite、`cargo fmt --check`、fixture node 测试、`git diff --check` 全绿。遗留：键入 stash 消息的运行时冒烟受键盘注入缺口限制，归 M4-08 手工门槛；Windows `stash@{N}` argv 引号差异未实测。
- [x] **M4-02** 实现合并与变基的发起、进行中状态、继续和中止。
  - 证据（2026-09-24，Linux / Git 2.53）：新模块 `inflight.rs`（检测）+ `sequencer.rs`（`merge_start`/`rebase_start`/`operation_continue`/`operation_abort`/`operation_skip` 5 命令）。**进行中检测**并入 `session::capture`：读 identity 的 git_dir（linked worktree 天然正确），快照新增 `operation: Option<OperationView>`（kind/subject/step/total）。标记矩阵：`MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD` 首行必须是合法完整 OID（否则 `unknown`，绝不猜）；`rebase-merge/`（head-name 出分支名、msgnum/end 出步数）与 `rebase-apply/`（next/last）识别为 rebase；多标记并存 → `unknown`；无标记但 status 有冲突条目 → `unknown`（"绝不伪装干净"）。标记文件存在但读失败 → 结构化 `inflight_read_failed` 上抛。8 项 `inflight::tests` 覆盖矩阵（含坏 OID、双标记、步数计数）。**冲突不是失败**：`Outcome::Conflicted`（serde "conflicted"，前端 TS 联合同步；conflicted 时 details=None，banner 接管）。发起命令闸门顺序：版本/裸库/未出生（`commit_context`）→ 在场操作复查（拒"already in progress"）→ 目标校验（仅完整 OID 或 `for-each-ref refs/heads/` 精确唯一名；`HEAD~1`/`@{u}`/远端名/空白全拒且 `exit_code: None` 证未触 Git）→ 取消短路 → `merge --no-edit <ref>` / `rebase <ref>`（600 s 超时档）。rc≠0 后**先刷新再分类**：重读快照仍有 operation/冲突 → Conflicted，否则 Failed+脱敏 details。continue/abort/skip **永不信客户端**：每次按重检测的 kind 分派（merge/rebase/cherry-pick/revert × --continue/--abort/--skip；merge 无 skip 档；unknown 一律拒"不会猜哪条命令收尾"）。**编辑器偏差**（实测钉死于 plan/04 §写入动作规则）：Git 2.53 下 `merge --continue` 与停点 `rebase --continue` 无编辑器时 fatal "Please supply the message"，唯二者走 `repo::user_git_command_noninteractive`（GIT_EDITOR=:，仅此两路径，其余保持用户环境原样）；`cherry-pick/revert --continue` 实测无需任何处理。UI：Changes 下 `#operation-banner`（subject+步数，Continue/Skip/Abort 仅由 kind 驱动渲染，unknown continue 出提交且消息为 Git 默认、rebase 冲突步数 (1 of 1)+skip 完成（HEAD=main）与 abort 复原原提交（reflog 兜底，无自动 force）、在场拒发起、坏目标矩阵未触 Git、空闲仓库 finish 命令拒 + 陈旧版本拒。全量 159 项 Rust 测试、9 项 node fixture、`tsc && vite build`、`cargo fmt --check`、`git diff --check` 通过（Linux 单平台）。遗留：banner/按钮的 AT-SPI 运行时冒烟与冲突解决键入流归 M4-08 手工门槛；Windows 上 `GIT_EDITOR=:` 语义未实测（已在 plan/04 记为平台缺口）；mergetool 解决路径在 M4-05。
